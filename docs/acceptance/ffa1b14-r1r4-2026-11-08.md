## 2. F17 / F18 审查

### 2.1 是否真的进入作用域（核心标准）

用真实引擎（`transcribe_melody`，`LOW_BASS_FILTER=off` 取候选，再复刻规则）：

| 指标 | F17 | F18 |
|---|---|---|
| GT 旋律 / 和声 | 24 / 18 | 16 / 17 |
| 引擎输出 | 42（off）/ 42（on） | 33 / 33 |
| 低音候选（pitch<57 且 reg−pitch≥16） | **18** | **8** |
| 逐音基准（±6s 75 分位） | 72 / 74 / 76（中位 74） | 74 / 76（中位 76） |
| 旧 R1 + 旧 R4 删除 | 18（全 r1） | 8（全 r4） |
| 新 R1 + 旧 R4 删除 | 18（全 r4） | 8（全 r4） |
| 旧 R1 + 新 R4 删除 | 18（全 r1） | 0 |
| **新 R1 + 新 R4 删除** | **0** | **0** |
| 复刻保留集 == 引擎 on 产物 | 是 | 是 |

结论：**F17 这次真的进了规则作用域**——基准被和声层抬到 72–76，18 个低音候选，两条修改**各自单独都不够**（只改 R1 或只改 R4 仍删 18），必须两条同时生效才 0 删除。F18 也按预期触发旧 R4 并全部保留。这一条通过。

### 2.2 低音句与嵌套保护

F17 低音句 A2–C3 含相邻 `45→57`（+12）、`57→48`（−9）与同音反复；旧规则下：
- 旧 R1 因「±0.5s 无高音旋律 + 低音连段」整段删 18；
- 新 R1 因低音句内部 1.5s 内存在同线（|Δ|≤16）旋律音而全部保留；
- 新 R4 再因「run 前后旋律音相差 ≤1」放行（F17 的两个下探点从前音 57 回到 57）。

注意：新 R1 的同线保护只在 1.5s 内、且 |Δpitch|≤16 时生效。**若真实低音句稀疏（相邻音间隔 >1.5s）且整体比高音层低 >16 半音，仍会被整段删**；F17 的低音句是连续的，覆盖不到这一形态。这是残留风险，不是本轮阻塞项。

### 2.3 precision 0.57 / leak 0.43 / dev +0.75 是什么

| | F17 | F18 |
|---|---|---|
| 预测音数 | 42 = 24 旋律 + 18 和声 | 33 = 16 旋律 + 17 和声 |
| precision | 24/42 = **0.571** | 16/33 = **0.485** |
| leak | 18/42 = **0.429** | 17/33 = **0.515** |
| note-count dev | 18/24 = **0.75** | 17/16 = **1.0625** |
| 验收阈值（旧 → 新） | 0.7/0.25/0.3 → **0.5/0.5/0.8** | 新增 → **0.45/0.55/1.1** |
| 阈值余量 | 0.071 / 0.071 / 0.05 | 0.035 / 0.035 / 0.04 |

判定：**这是 fixture 结构决定的，不是选线新 bug；但它同时说明这条 fixture 测不了“污染”。**

- F17 和声层在 0–4.0s 与 10.5–14.5s，旋律在 4.5–10.5s，**时间上完全不重叠**；F18 同理（和声 0–2.0s、6.24–8.0s，旋律 2.5–6.0s）。选线器在每个时段只看到一条线，必然把它收进来。18/18 和声、24/24 旋律全部检出，precision/leak/dev 恰好等于 GT 的旋律:和声比例。
- 因此它既不是“和声被错误选进旋律线”的新问题，也不是“fixture 设计正常现象”可以一笔带过——**真正的问题是这三个指标在这条 fixture 上不可作为质量判据**，而阈值从 0.7/0.25/0.3 放宽到 0.5/0.5/0.8（F18 0.45/0.55/1.1），恰好压在结构性值下方 0.03–0.07。它们只能拦住“漏检 >5 个和声/旋律”的粗差，拦不住任何选线污染。
- 处理要求：**把 F17/F18 的 precision、bass_leakage、note_count_deviation 标记为 diagnostic/skip**，门禁只保留 recall、segment_recall、below220 与「0 删除」。若确实想验证“同时响时和声会不会被当成旋律”，需要新增**时间上重叠**的和声 fixture（而不是现在的分段填充）；否则不要再用这三个数字声称选线质量。

## 3. 非确定性撤回的核验

- 开发方改口：`0.78/1.00` 与 `0.86/0.86` 来自 **R4 阈值 5 vs 6 的版本差异**，不是跨批随机；并给出 4 进程 dump 哈希相同。
- **「撤回主张」成立**：本机 F12-clean 4 个独立进程逐字段一致（沿用 `docs/acceptance/evidence/f12_clean_runs/`，4 份 SHA256 相同）；开发方新给的 4 进程哈希也一致。
- **「R4 阈值导致振幅差异」这个归因不成立**：`_suppress_low_interjections` 只决定删/留，振幅来自 basic-pitch，不经过任何按阈值归一化。实测 F17/F18 在 `LOW_BASS_FILTER` off/on 下**共有音振幅差异 = 0**；F12-clean 的碎片振幅仍是 `0.7828/0.5993` 与 `0.7865/0.6090`，从未出现 1.00 或 0.86。
- 要求：报告措辞写成「**未复现；跨批差异的原因未举证**」，不要写成「已确认为跨版本差异」。若坚持该解释，需附两批完整 dump 与命令，并说明为何阈值会改变振幅。

## 4. `REGISTER_GAP` 三档对照（`LOW_BASS_FILTER=on`，默认配置）

方法：`MELODY_CONTINUITY_REGISTER_GAP=12/14/16` 各跑一次无 Demucs 等价复现（原音频路径，与真实流水线同源），再用同一 `analyze.py`（复用 `storage/acceptance/analysis/ref_notes.json`）算指标。

| GAP | 音符 | 覆盖率 | leak | 跳变 | A3 以下 | 尾段低音（108–132s） | 吞音 |
|---|---|---|---|---|---|---|---|
| **12（默认）** | **367** | **80.2%** | **21.5%** | **44** | **11** | **0 / 72** | **41** |
| 14 | 375 | 80.2% | 23.2% | 55 | 13 | **2 / 75**（125.8s 42、126.0s 49） | 38 |
| 16 | 377 | 80.2% | 23.9% | 57 | 13 | **3 / 76**（113.8s 49、125.8s 42、126.0s 49） | 38 |

- **尾段低音随 GAP 上升而出现**（0 → 2 → 3），所以「三档都为 0」的停止条件未触发。
- 但方向是明确的：覆盖率三档都不变（80.2%），而 GAP 14/16 的 leak、跳变、A3 以下全部更差，多出的音是伴奏/内声部（尾段新增全是 `accompaniment/inner`）。**没有任何一个指标支持把 GAP 抬高。**
- 因此拆分的现实价值为零：只有在「想用 GAP≥14」时才需要把低音门槛与高音证据门槛分开来补尾段；而 GAP≥14 本身当前无收益。
- 结论：**不做拆分，保留 GAP=12**。若未来为了别的目标必须抬高 GAP，再重开这项评估；届时需要重跑本表并加看「高音证据阈值单独变化」对覆盖率/leak 的影响，不要只盯尾段。
