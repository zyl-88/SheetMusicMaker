# P1-4 复测报告（2026-11-07）

> 验收方独立复测，未修改任何产品代码。结论以本报告数据为准。

## 0. 结论摘要

1. **Fixture 层：P1-4a/4b 生效，无回归。** F11 0.29/0.25 → 1.00/1.00，F5 0/0 → 1.00/1.00，F6 低音 0/6 → 6/6（recall 0 → 1.00），F13 0.89 → 1.00；`legacy_nms` 与基线逐项一致，回滚开关有效。
2. **全曲交付层：不可信，存在时间轴漂移。** 音符数 298 → 488，但导出谱总长 **171.24 s**，音频只有 **139.44 s**，**111 个音符（22.7%）的起点落在音频结束之后**；覆盖率 31.9% → 15.0%、八度错 11.4% → 23.8%，这些恶化是漂移伪影。
3. **转录层：确有大幅提升。** 绕开量化器直接取 DP 选线裸输出：513 音、覆盖 138.08 s、**旋律覆盖率 80.8%**（基线口径 31.9%），其中 285 旋律（55.6%）、203 伴奏（39.6%），无越界时间。
4. **"488 个音可信不可信"的答案**：**音是真实检出的，不是凭空假音；但交付的乐谱不可信。** 根因是 quantizer「单声部去重叠」在音符变密后逐步把后续音符后推，累计 +31.8 s（独立复算 +33.2 s，吻合）。P1-4 的收益被量化器缺陷抵消，需先修量化器再谈指标。
5. 耗时：端到端 **221.5 s**（基线 394 s）；转录阶段 **7.1 s**（开发方自测 20.8 s，基线约 92 s），方向一致且更快。
6. **F7 的完整 pipeline 口径已改好，但端到端验证被产品侧阻塞**：复测后仓库推进到 `89486e4` 且 `transcriber.py` 有未提交的 `dump=` 调试改动，`dump` 参数与函数签名不一致导致 pipeline TypeError（basic-pitch 与 Melodia 两条路径都挂），本轮未能生成 F7 的 `comparison.md`。详见 §6。

## 4. 核心判断：488 个音可信不可信

### 4.1 交付 MIDI 的归类（漂移污染，不可直接采信）

| 类别 | 数量 | 占比 |
|---|---|---|
| top/melody | 64 | 13.1% |
| accompaniment/inner | 109 | 22.3% |
| octave-error | 116 | 23.8% |
| wrong-pitch | 66 | 13.5% |
| spurious(no-ref) | 124 | 25.4% |
| near-top | 9 | 1.8% |

"新增 190 个音里落在哪"：由于整条时间轴后移，**新增音几乎全部（483/488）不再与基线音符同 onset**（仅 5 个同音高 ±80 ms 保留），按交付谱去分类会把大量真实音误判成 `spurious` / `octave-error`。因此上表只能说明"谱面错位"，**不能**用来判断假音多少。

### 4.2 裸输出探针（正确时间轴，绕开量化器）

直接调用 `transcriber.transcribe_melody`（dp_register），取量化前的 513 个音符：

| 类别 | 数量 | 占比 |
|---|---|---|
| top/melody | 285 | 55.6% |
| near-top | 25 | 4.9% |
| accompaniment/inner | 203 | 39.6% |
| octave-error | 0 | 0.0% |
| wrong-pitch | 0 | 0.0% |
| spurious(no-ref) | 0 | 0.0% |

- **旋律覆盖率 80.8%**（基线 31.9%），音符覆盖到 138.08 s，无越界。
- 独立交叉校验（pYIN，非 basic-pitch 同源）：513 音中 **86 个（16.8%）** 在音符中段没有任何 pYIN 发声；基线交付 298 音中该比例为 **15.1%**。两者量级相当，**说明新增音并没有明显比基线更容易是假的**。
- 注意：`top/melody` 的参考本身就是 basic-pitch 对同一音频的输出，与转录同源；所以"0 无参考"只能证明与参考检出一致，不能证明绝对无假音。pYIN 才是独立证据。
- 残余问题：**39.6%（203/513）仍是伴奏/内声部**（低于顶层 ≥5 半音）。DP 在同一时刻取最高音，但旋律缺位的时刻会落到伴奏；这部分对"单声部主旋律"目标仍是噪声。

### 4.3 漂移根因（已复算）

`backend/app/services/quantizer.py` 的「消除重叠」逻辑：

```python
if start_q < cursor - 1e-6:
    start_q = cursor          # 后一个音被推到前一个音的结束
cursor = start_q + duration_q # 并把推后的时间继续传给后续音符
```

P1-4 让同时刻候选变多、选出的音符更密，重叠随之变多，后推量沿全曲累积。

| 证据 | 数值 |
|---|---|
| 交付谱总长 vs 音频 | 171.24 s vs 139.44 s（+31.8 s） |
| 总拍数 vs 自然拍数 | 460.93 vs 139.44×161.5/60 = 375.3（多 85.6 拍 ≈ 31.8 s） |
| 用裸输出按 quantizer 规则复算的累计后推 | **+33.2 s** |
| 起点在音频结束之后的音符 | **111 个（22.7%）** |

结论：**488 个音的内容可信、时间不可信。** 修好量化器后，覆盖率应回到 80% 量级；当前 15% 不能作为 P1-4 的成绩，也不能作为回退证据。
